# Lachesis 产品需求文档

## 1. 产品定义

Lachesis 是一个“个人生涯预演沙盘”。首版面向中国大陆、处于考研与就业选择期，且目标为计算机/软件/AI 相关专业与岗位的本科生。用户将履历、成绩、技能、家庭支持、预算、偏好、约束和候选路径输入系统；系统构建多个可追溯的未来世界，在教育、工作、生活关系和外部环境共同演化的时间线上进行重复仿真，最后给出路径对比、生命线、关键转折、敏感变量和可交互的反事实世界。

产品不输出决策建议或“唯一正确答案”。它的价值是预演以下可检验的问题：

- 在哪些条件下，直接工作比读研更合适？
- 将目标从普通院校提升到重点或顶尖院校，收益是否覆盖备考和延迟就业成本？
- 哪些因素会使当前结论反转，例如导师质量、行业周期、城市成本或个人的风险偏好？
- 如果两年后再转换路径，代价和可行性是什么？

## 2. 目标与边界

### 2.1 产品目标

1. 将模糊的个人选择转化为结构化路径和显式假设。
2. 对每条路径运行多个随机世界，输出生命线、分布、区间和失败分支，而非单一结果。
3. 让用户在时间线中修改变量，从最近快照分叉重新推演。
4. 让用户能追问“为什么”，并定位结论使用了哪些输入、证据和规则。

### 2.2 首版范围

- 路径：直接工作、两个或以上具体 Offer、备考后读研、备考失败后的回退路径，以及考研与工作之间的比较。
- 教育目标：冲刺、匹配、保底三组目标院校/专业分支。首版展示具体院校/专业的模拟录取区间，但不构成录取承诺。
- 时间跨度：固定为 1 年、3 年、5 年三档；前 12 个月按月推进，其后按季度聚合。
- 规模：默认每个路径运行 20 个随机种子；用户可选快速预演 10 个或深入预演 50 个，且不支持任意数量。每个世界包含 5 至 7 个环境/关系角色。
- 结果维度：职业资本、技能成长、收入与现金流、就业稳定性、职业发展速度、主观满意度、健康负荷、目标接近度和机会价值。
- 数据获取：首版不做实时全网爬取，只使用用户上传资料和运营人员上传、审核的官网公开数据。
- 官方数据目录：首版限定为 20 个计算机相关研究生项目和 6 个核心就业城市，由运营人员配置并版本化；目录之外的项目/城市只能作为数据不足的叙事路径，不能成为量化概率对象。
- 路径数量：一个案例最多同时比较 4 条路径。

### 2.3 非目标

- 不替代职业咨询师、心理治疗、招生录取或法律财务意见。
- 不生成“某人一定能考上某校”“某公司一定会录用你”一类确定性结论。
- 不在 MVP 中模拟所有城市、学校、专业和公司的完整现实细节。
- 不允许 LLM 直接修改收入、录取、晋升等结论性状态。
- 不提供总分、路径排名、推荐按钮或任何替用户做选择的功能。

## 3. 用户与任务

| 角色 | 核心任务 | 成功标准 |
| --- | --- | --- |
| 面临考研就业的本科生 | 预演不同选择下的人生轨迹 | 看见路径分叉、区间和关键事件 |
| 高投入备考者 | 设计冲刺、匹配、保底和失败回退方案 | 不把选择压缩为单点录取结果 |
| 家长或职业顾问 | 与用户共同理解路径假设 | 能保存并解释一份可复盘报告 |

## 4. 核心概念

- `个人基线`：教育、经历、技能、偏好、健康与财务约束的当前快照。
- `路径`：从当前状态出发的一组决策和条件，例如“工作两年后申请研究生”。
- `情景`：路径在某组外部假设下的具体版本，例如“行业下行、导师质量中等”。
- `世界运行`：情景在一个随机种子下的完整时间线。
- `干预`：用户在某一时间点改变变量，例如“薪资提高 20%”或“改为考取重点院校”。
- `结果分布`：同一路径的多个世界运行后形成的区间与概率，而非单一分数。

## 5. 用户流程

```text
创建案例
  -> 导入个人资料
  -> 生涯建模官持续追问并确认完整基线
  -> 设定目标和不可妥协约束
  -> 创建教育/工作候选路径
  -> 校准假设与证据
  -> 并行运行世界
  -> 先查看宏观路径树、生命线与关键分叉
  -> 进入比较报告、关系网络和角色对话
  -> 注入变量、从快照分叉、重新比较
```

## 6. 功能需求

### FR-01 个人基线与约束

用户可导入 PDF、DOCX、图片资料，也可使用手动表单。生涯建模官负责提取信息、预填字段、追问缺失项并回显待确认的结构化档案。该 Agent 不参与未来世界角色扮演。首次运行前用户必须一次性确认：本科院校与专业、年级/预计毕业时间、GPA 或排名、英语/证书、核心技能、实习/项目、目标城市、可支配预算、家庭支持、健康/时间约束和长期目标。每个字段都标记为“用户事实、用户估计或未知”。

验收：用户可在一次建模会话中完成必填档案；缺失的必填信息必须由建模官追问，不允许以静默默认值替代。

### FR-02 路径建模

用户可建立直接工作、多个具体 Offer、读研和混合路径。即使没有真实 Offer，用户也可创建假设工作路径，并手动填写目标岗位、行业、城市、薪酬范围、团队规模和成长机会。读研路径通过冲刺、匹配、保底目标院校/专业建立多个录取分支，必须包含备考周期、学费/生活成本和未录取回退策略。

验收：每条路径都有开始条件、时间长度、成功/失败事件和下一步分支。

### FR-03 假设与证据台账

系统展示每项影响因素的来源：用户输入、用户上传公开资料、平台运营人员上传并审核的官方资料、模型默认值或模拟假设。首版不进行实时全网爬取。用户上传数据只影响该用户案例；只有运营人员经过人工审核的官方资料才能成为全局默认数据，即使资料带有官网链接也不能跳过审核。只有记录了来源链接、发布日期和适用年份的证据，才能影响录取概率、收入或职业发展速度。若找不到与具体学校、专业和用户画像匹配的合格数据，系统必须标记“数据不足”，不得给出伪精确的录取概率；此时仅展示情景叙事和需补充的数据。用户可覆盖个人假设，并查看该值影响哪些路径和指标。

验收：报告中的每个结论至少能回溯到一个输入、规则或运行聚合结果。

### FR-04 并行仿真与可复现性

系统可对每条情景运行快速 10、标准 20、深入 50 三档随机种子。每次运行必须保存引擎版本、规则版本、输入版本、随机种子和事件日志。

验收：同一输入、版本和种子可重现相同确定性结果；LLM 输出必须缓存并记录模型版本。

个人资料只能发送至经过平台配置、承诺不将数据用于训练的模型服务。原始成绩单、预算、家庭支持和其他敏感输入不得直接发送至未经确认的第三方 API。

### FR-05 多维比较报告

报告展示路径间的宏观生命线、中位数、P10/P90 区间、模拟录取概率、收入区间、职业发展速度、主要风险、关键机会和结论反转条件。每个结论必须标注且只能标注为 `用户事实`、`官方数据`、`模型假设` 或 `模拟结果` 之一。报告首页固定展示“这是基于用户资料、官方数据和模型假设的模拟，不是录取或职业结果承诺”。不得输出总分、路径排名、推荐路径或确定性承诺。

验收：至少支持收入与现金流、职业资本、技能、稳定性、满意度和压力六个维度；用户可调整权重但原始维度保持可见。

### FR-09 异步运行与路径可信度

所有世界运行均为异步任务。用户可查看已完成世界数、总世界数、数据版本、规则版本和失败随机种子；首版不承诺实时逐事件动画或秒级完成。

真实 Offer 与假设 Offer 必须在路径树、报告和导出内容中使用不同的可信度标签。假设 Offer 固定标为 `假设路径`，不得与真实 Offer 使用相同标签或表述。

验收：用户能够查看每次运行的完成数量、失败种子与版本；任何假设 Offer 在所有展示位置均显示 `假设路径`。

### FR-06 未来世界与角色互动

用户可以浏览任一世界的宏观生命线、月度/季度事件、关系网络和状态变化，并与个人分身、导师、直属老板、招聘经理、家人、朋友和行业观察员对话。世界角色只能在仿真完成后基于该世界截至当前时点的记忆进行只读对话，不能承担资料收集、档案校验、触发事件或改写结果职责；用户必须创建分叉才能改变未来。首版关系角色由系统根据个人档案自动生成匿名角色，运行前不要求用户逐一确认，且不提供手动编辑入口；用户只能通过补充自己的事实资料间接影响角色生成。关系 Agent 只能影响由规则限定的机会概率，例如导师支持影响实习机会、经理反馈影响项目机会；不得直接决定录取、升职或收入。对话回复必须引用该世界的状态和事件，不能编造未发生的经历。

验收：用户能从报告跳转至造成某项结果的事件；角色对话返回世界 ID、时间点和引用事件。

### FR-10 最小化角色上下文与 LLM 事件校验

世界角色只接收完成角色任务所需的派生属性，例如家庭支持等级、预算等级、城市限制和技能状态；不得接收原始成绩单、具体家庭描述或上传文件。所有 LLM 提议事件必须通过结构化规则校验，并映射到已有规则、用户输入或证据；无法校验的内容只能作为叙事，不能影响任何指标。

验收：角色上下文审计中不存在原始附件或敏感原文；任一影响指标的 LLM 事件均可追溯到规则、输入或证据。

### FR-07 变量注入与分叉

用户只能在当前或历史时间点改变可控前因：接受何种 Offer、报考目标、是否参加培训、学习时间、是否接受实习、是否跳槽、城市选择或家庭约束。系统不允许直接修改录取、升职、收入等结果；结果必须由后续规则重算。每次干预生成新情景版本，基线世界不可覆盖。

验收：分叉结果可与基线进行逐维差分，并显示“此结论变化由哪些变量导致”。

### FR-08 报告快照与账号

用户可以保存报告。保存操作生成不可变快照，包含个人输入版本、证据数据版本、规则/引擎版本、随机种子范围、路径生命线、聚合指标和报告结论；后续修改案例不得覆盖已保存报告。

首版需要账号与案例所有权控制，但不支持跨设备访问、同步或恢复。账号会话、上传文件、案例数据和报告均绑定当前设备；设备丢失或更换后数据不可恢复，产品必须在注册时获得用户确认并清晰告知此限制。

验收：已保存报告可从当前设备账号下完整回放；修改路径或重新运行后，旧报告仍可读取其原始输入与证据版本。用户可导出 PDF，导出内容不得包含原始成绩单、预算、家庭支持或其他敏感资料。

## 7. 决策指标

所有指标取 0-100 标准分并保留原始量纲，权重由用户设定。默认指标如下：

| 指标 | 说明 | 例子 |
| --- | --- | --- |
| 职业资本 | 学历信号、项目经历、人脉和市场可迁移性 | 顶尖实验室项目与行业实习的组合 |
| 技能成长 | 与目标岗位的技能距离缩小程度 | 工程、研究、管理或语言能力 |
| 财务韧性 | 收入、成本、现金流和风险缓冲 | 学费、延迟收入、家庭支持 |
| 就业稳定性 | 找到合适岗位并持续就业的概率 | 行业需求、公司风险、可替代性 |
| 生活质量 | 压力、时间自主性、地理与关系匹配 | 长期高负荷不可被高薪自动抵消 |
| 目标接近度 | 对用户长期目标的直接贡献 | 进入目标领域、读博、定居或创业 |

## 8. 成功指标

- 从创建案例到完成可运行档案的中位时长小于 30 分钟。
- 70% 以上完成案例的用户至少创建一次前因变量分叉。
- 80% 以上报告结论具有可定位的输入和事件证据。
- 已完成用户最常见的后续动作依次为：保存报告、创建新分支、继续与建模官讨论。

## 9. 风险、隐私与伦理

- 履历、收入、健康和家庭资料均为高敏感个人数据；必须默认私有、支持永久删除和导出。
- 首版账号与数据绑定当前设备，不支持跨设备同步；不得向用户暗示数据可在其他设备恢复。
- 系统必须标注模拟、事实、估计和未知，禁止将生成内容伪装成统计事实。
- 不得基于受保护特征给出歧视性机会判断；涉及此类变量时只能在用户主动声明的约束下进行审计与解释。
- 对重大结论显示不确定性警告和建议复核项。
