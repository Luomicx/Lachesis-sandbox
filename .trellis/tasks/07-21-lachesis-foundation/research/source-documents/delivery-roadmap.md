# Lachesis 交付路线图

## 1. 里程碑

| 阶段 | 周期 | 目标 | 主要交付物 |
| --- | --- | --- | --- |
| P0 领域验证 | 2 周 | 固化规则、指标和假设边界 | 路径规则表、访谈记录、匿名样例 |
| P1 可运行 MVP | 6-8 周 | 完成考研、两个 Offer、回退等路径和不超过五年的世界仿真 | Mesa/SimPy 内核、案例表单、比较页 |
| P2 可交互世界 | 4-6 周 | 支持世界查看、角色对话和变量分叉 | 快照、事件台账、Future World 工作台 |
| P3 校准与安全 | 4 周 | 提升可复核性和敏感数据保护 | 证据台账、审计、删除、偏差测试 |
| P4 扩展 | 持续 | 更多专业、地区、教育与工作路径 | 插件化规则与数据适配器 |

## 2. P0 领域验证

必须先完成以下工作，不能直接开始大规模 Agent 开发：

- 与 5-10 位计算机/软件/AI 相关专业的真实用户和职业顾问确认“人生预演而非决策推荐”的问题表述、指标和不可接受的结论方式。
- 为“直接工作”“读研成功”“读研失败后工作”写出状态机和事件表。
- 定义用户/运营人员上传官网公开数据的人工审核和版本流程；首版不引入实时全网爬取，明确每个默认概率/范围的来源或标记为待校准假设。
- 定义单设备账号绑定、案例所有权、不可变报告快照和物理删除流程。
- 验证资料解析的预填、必填项追问、完整档案确认、脱敏 PDF 导出和不可恢复设备丢失提示。
- 选取 10 个匿名合成案例，人工演算预期方向并作为回归基线。

## 3. P1 MVP 切分

### 后端

- 实现 `CareerWorld`、`PersonAgent`、`SchoolAgent`、`OrganizationAgent` 和 `MarketAgent`。
- 实现教育、求职、就业、现金流、冲击五类 SimPy 过程。
- 支持 10/20/50 三档种子批量运行、快照、事件日志、聚合统计和可重试任务。
- 支持报告不可变快照、用户上传数据的案例隔离，以及审核官方数据的全局版本控制。
- 实现独立的生涯建模官与世界角色边界；先不接入自由世界角色对话，使用确定性规则和模板化解释。

### 前端

- 完成 PDF、DOCX、图片、手动表单导入，以及生涯建模官的持续追问与完整基线确认。
- 完成真实/假设 Offer、考研冲刺/匹配/保底、回退路径、路径树、假设确认和异步运行进度。
- 每个案例限制为最多 4 条路径；官方项目/城市目录由运营人员版本化管理。
- 完成宏观生命线、关系网络、区间对比、关键条件、失败分支和敏感性表；不提供总分、排序或推荐。
- 保留 MiroFish 的项目/运行/报告框架，但移除 Twitter/Reddit 平台概念。

### MVP 验收

- 考研、两个 Offer、考研失败回退等至少四条路径各运行 20 个种子，在普通开发机上可完成。
- 1 年、3 年、5 年三档时间线均可运行；缺少匹配官方数据时不生成伪精确录取概率。
- 目录仅含 20 个目标研究生项目和 6 个核心就业城市；异步运行状态显示完成数量、版本与失败种子。
- 用户能改变报考目标、是否接受 Offer/培训/实习、学习投入或跳槽等前因后获得新版本。
- 每个关键指标都能定位到事件和规则版本。
- 相同案例、版本和随机种子可复现。
- 已保存报告在当前设备可完整回放，且不会被后续案例修改覆盖。

## 5. 测试策略

- 单元测试：状态迁移、概率边界、现金流、资格与回退规则。
- 集成测试：同一种子可重现、分叉不修改基线、任务失败可恢复。
- 统计测试：增加学校质量或学习投入时，相关结果方向符合预定义的单调性或阈值规则。
- 回归测试：合成案例的指标区间、关键事件和报告引用保持稳定。
- 人工评审：职业专家审阅假设，不以 LLM 文案流畅度替代模型有效性。
- 安全测试：所有案例查询执行所有权校验；删除请求覆盖附件、快照、缓存和检索索引。
- 导出测试：PDF 不得包含原始附件、预算、家庭支持或其他敏感输入；网络证据缺少来源链接、发布日期或适用年份时不得进入计算。
- 模型服务测试：未经受信任配置的模型端点不得接收个人敏感资料。
- 证据标签测试：每项报告结论恰好拥有 `用户事实`、`官方数据`、`模型假设`、`模拟结果` 之一，不能缺失或混用。
- 体验测试：报告首页出现固定免责声明；界面没有总分、路径排序、推荐按钮；假设 Offer 在所有视图和导出中标记为 `假设路径`。
- 边界测试：世界角色只能在仿真完成后只读对话；角色上下文没有原始敏感资料；任何影响指标的 LLM 事件都具有规则、输入或证据关联。

## 6. 主要风险与缓解

| 风险 | 缓解策略 |
| --- | --- |
| 模型看起来过度精确 | 始终展示区间、样本数、假设和结论反转条件 |
| 学校/行业数据不充分 | 采用层级化抽象，标记默认值，允许用户校准 |
| LLM 幻觉污染结果 | LLM 输出只作为候选事件，规则引擎拥有最终写入权 |
| 运行成本过高 | 使用规则优先、缓存 LLM、并行种子上限和快照增量重算 |
| 敏感个人数据泄漏 | PII 加密、默认私有、最小化外发、可验证删除 |
| 结论造成心理压力 | 用条件性语言呈现，提供风险解释和人工咨询边界提示 |

## 7. 团队配置

最小团队：1 名产品/领域负责人、1 名后端仿真工程师、1 名前端工程师、1 名数据/规则工程师；P2 后可增加 1 名 LLM 工程师。职业顾问和教育/招聘领域专家以每周评审方式参与，不应被 LLM 替代。
