# Lachesis 交互与体验设计

## 1. 信息架构

```text
案例列表
  -> 生涯建模官
       -> 导入资料 / 持续追问 / 确认个人基线
  -> 案例编辑器
       -> 目标与约束 / 候选路径 / 假设台账
  -> 运行中心
       -> 情景版本 / 运行进度 / 失败与重试
  -> 决策比较
       -> 多维分布 / 敏感性 / 可逆性 / 报告
  -> 未来世界
       -> 时间线 / 状态地图 / 关系网络 / 角色对话 / 变量注入
```

## 2. 案例编辑器

采用“导入资料 + 生涯建模官预填与持续追问 + 确认表单”模式。用户不能跳过影响仿真有效性的核心字段；首次运行前必须完成一次完整档案确认。

1. `你现在在哪里`：本科院校与专业、GPA/排名、经历、技能、资金、城市、时间与家庭约束。
2. `你想去哪里`：目标岗位、行业、城市、收入、研究兴趣和生活偏好。
3. `你正在比较什么`：创建工作、读研和回退路径；一个案例最多保留 4 条路径。
4. `哪些条件不能妥协`：如现金流底线、地理约束、最长备考期。
5. `哪些内容只是估计`：显式检查不确定输入。

每项字段旁显示来源标签：`用户事实`、`用户估计`、`用户上传资料`、`审核官方数据`、`系统默认`、`未知`。未补齐的必填字段应保留在建模官的追问队列中，不能启动运行。用户上传资料只服务于当前案例；只有人工审核通过的官网资料才会显示为全局默认数据。首版不显示实时全网检索结果。

工作路径既可以录入真实 Offer，也可以建立假设工作路径；假设路径必须明确标记，且需要填写目标岗位、城市、薪酬范围、团队规模和成长机会。

## 3. 比较报告

顶部不显示“最佳路径”大卡片。用户首次进入结果时，先展示固定免责声明“这是基于用户资料、官方数据和模型假设的模拟，不是录取或职业结果承诺”，再展示宏观路径树、不同世界的生命线缩略图和三个最重要的分叉事件；之后进入单条路径的详细比较。首屏应展示：

- 每条路径的身份标签与主要前提。
- 六项指标的区间带与中位数，而非只有雷达图。
- 不同指标在不同路径下的区间变化与条件，不显示总分或路径排序。
- 三条最关键的结论条件，例如“只有录取重点层级且获得高质量实习时，读研路径在职业资本上稳定领先”。

报告的每一段结论均可展开为“依据”：输入、假设、事件样本、统计范围与相反结果样本。每个结论标题固定显示单一来源标签：`用户事实`、`官方数据`、`模型假设` 或 `模拟结果`。真实 Offer 与假设 Offer 使用不同标签；假设 Offer 必须显示为 `假设路径`。

当某学校/专业缺少匹配的合格官方数据时，录取概率位置显示“数据不足”，并列出需补充的数据；界面不得以宽泛数值区间伪装为量化结论。

## 4. 未来世界工作台

工作台采用三栏，不嵌套卡片；首版不做 2.5D 场景、角色移动或实时动画：

```text
左：路径树与世界选择
中：前 12 个月按月、之后按季度的可缩放生命线
右：该时点的个人状态、事件依据、关系网络和角色对话
```

运行前用户通过固定分段控件选择 `快速预演（10）`、`标准预演（20）` 或 `深入预演（50）`，以及 `1 年 / 3 年 / 5 年` 时间跨度；不提供自由数字输入。运行中显示已完成世界数、总世界数、数据版本、规则版本和失败种子，不承诺逐事件动画或秒级完成。

时间线事件采用清晰分类：教育、求职、工作、关系、市场、冲击和用户干预。用户点选事件后看到状态差分，例如“第 14 月获得实习，使目标技能距离下降 12 点，现金流上升 8 点”。关系网络复用 MiroFish 图谱视图的可探索模式，展示与家人、朋友、导师、同学、同事、直属老板之间的支持和影响关系。自动生成的关系角色无需在运行前确认；其影响仅能改变受规则限制的机会概率，不得直接改变录取、升职或收入结果。

## 5. 变量注入

变量注入采用右侧抽屉：选择时间点、可控前因、取值或范围、影响范围和分叉名称。录取、升职和收入等结果字段不可直接编辑。提交前明确告知：

- 会创建一个新的情景版本。
- 从哪个快照继续。
- 哪些后续事件必须重算。
- 基线不会被修改。

重算完成后展示基线与分叉的差分时间线，并可过滤“因干预变化”的事件。

## 6. 角色对话

对话对象包括个人分身、导师、直属老板、招聘经理和行业观察员。生涯建模官与世界角色严格分离：建模官只在仿真前收集和校验资料；世界角色只在仿真完成后基于当前世界记忆进行只读对话。对话界面不提供“让角色改变世界”的操作，用户必须通过创建分叉改变未来。关系角色由系统自动生成，首版没有独立编辑入口；用户补充个人事实后可触发后续分叉中的角色重新生成。对话窗口必须展示当前世界、时间点、角色身份和可用记忆范围。回答底部显示引用的事件，不允许跨世界或跨未来时点泄露信息。

## 7. 报告保存与设备限制

保存报告时，系统生成不可变版本快照，显示输入、公开数据、规则和运行版本，便于之后从当前设备完整回放，并支持导出已脱敏 PDF。首版账号及数据绑定当前设备，不提供跨设备登录、同步或恢复入口；设备丢失或更换后数据不可恢复，首次注册和保存报告时必须显式提示并获得确认。

## 8. 状态与错误体验

- 输入不完整：指出具体缺失项，并由建模官继续追问；未完成必填基线不得开始运行。
- 正在运行：显示“已完成世界数/总数、当前版本、预计剩余时间”，而非伪造精确进度。
- 部分失败：保留成功世界，说明失败种子和重试入口。
- 结论不稳：显示“结论对 X 高度敏感”，而不是隐藏冲突样本。
- 风险提示：当用户将高敏感变量或未校准数据作为主要依据时，显示限制说明。
